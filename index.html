Secure network for a three-floor law firm

A network for 22 users and 30 devices across three floors and a server room, built around one rule: client files must stay private.

Challenge

In a law firm, a flat network is a liability. Staff, devices and servers needed to be separated so that access to client data is deliberate, not accidental.

What I did

Designed the topology and addressing first, then configured, tested and documented the whole network.

Key decisions

  • VLANsSix VLANs segment users and the server room, with inter-VLAN routing between them.
  • ACLsAccess lists control which segments may reach the servers that hold client files.
  • OSPFDynamic routing across the network, with DHCP for addressing and NAT for outbound access.
  • SSHDevice management hardened with SSH instead of open remote access.

Process

How I build a network

Design comes first. Configuration is the easy part once the plan is sound.

  1. Requirements

    Who needs access to what, and what must stay private.

  2. Design

    Topology, addressing and VLAN plan, drawn before any command is typed.

  3. Configure

    Switching, routing, DHCP and NAT in Cisco Packet Tracer.

  4. Test and harden

    Verify what should work, prove what should be blocked, lock down management with ACLs and SSH.

  5. Document

    Configs, test results and a clear write-up committed to GitHub.
